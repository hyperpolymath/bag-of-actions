= bag-of-actions — secret store & key rotation (Phase 1.6)
:toc: macro

The fail-closed attestation (link:ci-check-baton.adoc[]) needs two secrets on every
node. This is the operational procedure for distributing and rotating them.

WARNING: This procedure uses `age` for the *shared* secret. `age` is not assumed
present in every environment; install it from Guix (`guix install age`) on a node
before running these steps. No Python / Nix / npm is involved.

toc::[]

== The two secrets

[cols="1,3",options="header"]
|===
| Secret | Distribution
| `BAG_ATTEST_KEY` (shared HMAC key, ≥ 32 bytes) | encrypted with `age`, decrypted into the per-node env / keyring (below)
| ed25519 signing key (`~/.ssh/id_ed25519_signing`) | *per-node*, never shared; only the public key travels (inside the envelope)
|===

The shared key proves integrity + that the verdict came from a node holding the
estate secret; the per-node signing key proves *which* node. `id_ed25519` (auth) is
NOT used for signing.

== Distributing the shared key with `age`

Encrypt once, to each node's age recipient (an age key, or its SSH ed25519 key):

[source,sh]
----
# generate the shared key (do this once, offline)
head -c 48 /dev/urandom | base64 > attest-key.txt      # >= 32 bytes after decode

# encrypt to each node (reuse the node's SSH ed25519 *public* key as a recipient)
age -R mesh-server-1_ed25519.pub -R mesh-laptop_ed25519.pub \
    -o attest-key.age attest-key.txt
shred -u attest-key.txt
----

On each node, decrypt at boot into the env file (root-only), never to a world-
readable path:

[source,sh]
----
age -d -i ~/.ssh/id_ed25519 attest-key.age | install -m 600 /dev/stdin /etc/bag/attest-key
# /etc/bag/bag.env then sets:  BAG_ATTEST_KEY="$(cat /etc/bag/attest-key)"
----

== `key_id` keyring layout (rotation)

The host selects the verifying key on thaw by the envelope's `key_id`
(`BAG_ATTEST_KEY_ID`, default `default`). Keys live in a keyring directory:

----
~/.config/bag/attest-keys/
  default            # current active key (mode 600)
  2026-06-rotation   # previous key, kept during the overlap window
----

`key_id` is validated (`[A-Za-z0-9._-]`, no `..`); a path-traversal id resolves to
no key, i.e. a rejected verdict.

== Rotating the shared key (zero-downtime overlap)

. *Stage* — write the NEW key to `~/.config/bag/attest-keys/<new-id>` on every node;
  leave the old key in place. Both are now resolvable on thaw.
. *Cut freezing over* — set `BAG_ATTEST_KEY` to the new key and
  `BAG_ATTEST_KEY_ID=<new-id>` on each node. New verdicts freeze under `<new-id>`;
  old verdicts still thaw because the old key is still in the keyring.
. *Drain* — once no in-flight verdict references the old id (check the ledger /
  custody chain, Phase 3), delete the old keyring file on every node.

Because `key_id` is bound into the canonical string, a verdict frozen under one id
can never verify under another — a stale or wrong key fails closed.

== Per-node signing key

Stays at `~/.ssh/id_ed25519_signing` (or `BAG_SIGN_KEY_PATH`), unencrypted ed25519,
mode 600, loaded into `ssh-agent`. It is *never* distributed; rotating it is simply
generating a new key on that node — the new public key travels in subsequent
envelopes automatically (self-contained verification, no out-of-band lookup).
