This file provides implementation receipts and formal evidence for the 
claims made in README.adoc. It is intended for developers auditing the 
integrity of the continuation mesh.

== Claim-to-implementation map

=== Linear Baton Logic

[quote, README.adoc]
____
Powered by Ephapax, ensuring one-time consumption of resources.
____

How this is implemented::
The Baton is modeled as a linear resource in **Ephapax**. In the current POC, 
linearity is enforced by the **Elixir Orchestrator** which ensures a Baton 
is only "claimed" by one process at a time via GenServer casts. 
The underlying Wasm logic in `counter.wat` represents the atomic 
transition step.

Code Paths::
* link:counter.wat[] — Wasm logic for the atomic transition.
* link:bag/lib/bag/baton.ex[] — Elixir struct representing the Baton.

Caveat::
Full language-level linearity (Ephapax `let!`) is validated during 
compilation but Milestone 2 relies on Elixir process isolation for 
runtime non-duplication.

=== Mobile Wasm Contexts

[quote, README.adoc]
____
Native state capture of WebAssembly modules for seamless migration.
____

How this is implemented::
The **Zig Execution Host** manages the Wasm lifecycle. It captures 
the result of a Wasm execution (currently via function return values 
and CLI output) and serializes it into the persistent Baton store 
(`baton.txt`). 

Code Paths::
* link:src/main.zig[] — Zig host logic for Wasm invocation and state capture.
* link:bag/lib/bag/executor.ex[] — Elixir bridge that invokes the Zig runner.

Caveat::
Milestone 1/2 uses function arguments for state. Full linear memory 
snapshotting (dumping the `memory` section) is planned for Milestone 3.

=== Polylingual Mesh

[quote, README.adoc]
____
Orchestrated by Elixir, executed by Zig, proven by Idris.
____

How this is implemented::
The system boundary is governed by a **Verified ABI** defined in **Idris 2**. 
Routing decisions in the Elixir mesh are no longer random; they are 
bridged to the **Zig Execution Host** which implements the formal 
`Bag.Estate` capability matcher (hand-translated from the Idris 2 spec). 
Every Baton handoff is verified against the target node's hardware and 
trust traits before migration.

Code Paths::
* link:verification/proofs/Bag/Protocol.idr[] — Formal capability algebra.
* link:src/estate.zig[] — Zig implementation of the formal matcher.
* link:bag/lib/bag/mesh.ex[] — Elixir routing logic using the verified bridge.

=== Guix-Powered Builds

[quote, README.adoc]
____
Integrated Guix orchestration for reproducible artifact creation.
____

How this is implemented::
The **Zig Execution Host** provides a native interface to the **Guix** 
package manager. Before a Wasm transition occurs, the host can 
trigger a `guix build` based on the Baton's requirements. This allows 
mobile continuations to not just carry state, but to *build their 
own execution environment* (or dependencies) reproducibly as they 
move across the mesh.

Code Paths::
* link:src/main.zig[] — `runGuixBuild` function in the Zig host.
* link:bag/lib/bag/baton.ex[] — `guix_package` field in the Baton metadata.

Caveat::
Current implementation uses the `guix` CLI. Future versions will move 
to a direct Guix-Daemon socket interface for improved isolation and 
performance.

=== Formal Estate Manifest

[quote, README.adoc]
____
Verified mapping of infrastructure capabilities to physical nodes.
____

How this is implemented::
The **Estate Manifest** is defined in **Idris 2** as a static, verified 
registry of nodes and their capabilities. This allows the system 
to perform "Capability Algebra" at compile-time or run-time to 
ensure that a Baton's requirements (e.g. `[GPU, Guix]`) are 
physically satisfiable by at least one node in the mesh before 
a handoff is even attempted.

Code Paths::
* link:verification/proofs/Bag/Estate.idr[] — Formal node registry.
* link:nodes.scm[] — Guix-native mirror of the estate configuration.

Caveat::
Current registry is static. Future work will include dynamic node 
attestation (via a "Hello" handshake) to update the manifest 
in real-time as nodes join the mesh.

== Known gaps

implementation only transfers the `counter` integer. True memory snapshotting 
is tracked in Issue #3.

====

yet invoked at runtime by the Elixir orchestrator.
